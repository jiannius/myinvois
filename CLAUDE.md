# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Laravel package (PSR-4 `Jiannius\Myinvois\`) that integrates with the Malaysian LHDN MyInvois e-invoicing API. It builds UBL 2.1 JSON invoice documents, signs them with XAdES, submits them to MyInvois, and tracks lifecycle state in an `myinvois_documents` table. There is a PHPUnit test suite (`composer test`, see "Testing" below) but no build step and no lint config — it's a library consumed by host Laravel apps. Auto-discovered via `MyinvoisServiceProvider`, which binds the singleton-style `myinvois` container key to a fresh `Myinvois` instance.

## Entry point and call flow

`src/Myinvois.php` is the only public surface. Typical usage from a host app:

```php
app('myinvois')
    ->setClientId(...)->setClientSecret(...)->setPrivateKey(...)->setCertificate(...)
    ->submitDocuments([$normalizedDocument]);
```

Settings cascade: explicit `set*()` → `config('services.myinvois.*')` → preprod toggle defaults to `!app()->environment('production')`. HTTP timeouts follow the same cascade (`setConnectTimeout()` / `setTimeout()` → `services.myinvois.connect_timeout` / `timeout` → defaults 10s / 60s, via `resolveTimeout()`; non-positive or non-numeric values are ignored since 0 would mean "wait forever") and are applied to both the token request in `getToken()` and `sendRequest()`. 60s is deliberately generous for a large `documentsubmissions` POST -- do not lower the default casually. Laravel's own defaults were already connect 10s / total 30s, so the SDK only makes them explicit and configurable (the default total is a raise). The post-submit poll in `createMyinvoisDocuments()` goes through `pollSubmission()`, which sets a temporary `$timeoutCap` of `POLL_TIMEOUT` (15s) in try/finally (restored even on failure); `getRequestTimeout()` applies `min(configured, cap)` to both the token request and `sendRequest()`, so a lower configured timeout is kept and a direct public `getSubmission()` is unaffected. The MyInvois OAuth token is cached under `myinvois_<clientId>_<onBehalfOf>` for 50 minutes. `callApi()` enforces per-endpoint rate limits via Laravel `RateLimiter` (sleeps when capped) — preserve the `perMinute` values when adding new endpoints; they mirror LHDN's published limits. The limiter key (`getThrottleKey()`) is the endpoint with ids stripped (only the segments in `THROTTLE_LITERALS` survive, anything else becomes `id`; add a new endpoint's literal words there) plus the client id: LHDN limits are per client id (TJ, 2026-10-12), so every uid shares one counter and client ids never do. A client told `withoutThrottleSleep()` (the queue jobs) throws `MyinvoisThrottledException` (a 429 `MyinvoisUnavailableException` with `getRetryAfter()`, nothing sent) instead of sleeping.

Submission pipeline inside `submitDocuments()`:

1. `UBL::build($document)` — converts the flat normalized array (see `Helpers/Sample.php` for the canonical shape) into the deep nested UBL `Invoice.0.…` structure expected by MyInvois. Built up section-by-section via `getDocument*Schema()` methods.
2. `Signature::build($document, $privateKey, $certificate)` — computes XAdES enveloped signature: cert digest, doc digest (canonical minified JSON), `openssl_sign` with SHA256, signed-properties digest, then populates the `UBLExtensions` and `Signature` blocks. The signing JSON must use `JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES` with no whitespace — `Signature::toJson()` is the single source of truth.
3. JSON is base64-encoded with a SHA256 hash and POSTed to `documentsubmissions`.
4. `createMyinvoisDocuments()` persists one `MyinvoisDocument` row per accepted document — except for consolidated submissions, where one row is created per *line item* with the line description as `document_number` and the parent invoice number as `consolidate_number`. Detection runs per-document via `UBL::isConsolidated($document)`.
5. After submission, polls `getSubmission()` up to 3 times with 2s sleeps to flip `submitted` → `valid`/`invalid` immediately (`pollAfterSubmit()`; skipped by `withoutPolling()`). `createMyinvoisDocuments()` is the public persist-then-poll pair; the persist half is `persistMyinvoisDocuments()`, which `submitDocuments()` calls directly so it can free the lock between the two..

## API failure handling

`callApi()` / `getToken()` are the single place failures become exceptions (`src/Exceptions/`, all extend `MyinvoisException` -> `RuntimeException`): network `ConnectionException`, 5xx, 429 and a token response without `access_token` -> `MyinvoisUnavailableException` (network failures expose a sanitised `getReason()`; 429 keeps `Retry-After`; a token 408 is treated like 429); 4xx from `/connect/token` (except 408/429) and a 401 that survives one retry -> `MyinvoisAuthenticationException`; 403 -> `MyinvoisPermissionException` (thrown before `failedCallback`, as before). Other 4xx are deliberately **returned**, not thrown -- callers rely on LHDN's JSON rejection body (`submitDocuments`, `validateTaxpayerTIN` false on 404, `searchTaxpayerTIN` null on 404). On a 401 `callApi()` `cache()->forget()`s the token (`getTokenCacheKey()`) and retries once with a fresh token (no loop). `failedCallback` runs once, on the final response, and its return value replaces the response when it is a `Response`; any other return (e.g. `null` from a callback that only logs) keeps the original failed response, so `$api->json()` is never called on null. The throw check happens on the post-callback response. The post-submit status poll in `createMyinvoisDocuments()` catches `MyinvoisException` and stops: the documents are already accepted and saved, so it must never throw. Configuration errors (missing client id/secret, key/certificate, preprod credentials) stay plain `\Exception` on purpose. A timeout is a `ConnectionException`, so it becomes `MyinvoisUnavailableException` (and after a `submitDocuments()` timeout the submission may still have reached LHDN). `rejectDocument()` throws `\InvalidArgumentException` before any network call when `$reason` is blank (LHDN requires it); `cancelDocument()` is deliberately left lenient (works on preprod today) although LHDN requires a reason there too. `rejectDocument()` is a `PUT` like `cancelDocument()` but deliberately writes **no** local state: it is the buyer rejecting a received document (the row may be absent or inbound, LHDN answers "requested", and `rejected` is not a `Status` case). Any method that writes local state from a response (`cancelDocument`, `getDocumentDetails`) must only do so when `$api->successful()` and the body decoded to an array. Exceptions keep only status/endpoint (query stripped)/raw body strings, never the Response object (it holds the bearer token) and never the original `ConnectionException` as `previous` (its Guzzle request carries the `Authorization` header / `client_secret` and the full URL). Known limitation: `MyinvoisFake` cannot simulate these failures. Keep the boost guideline and README in sync if this changes.

## Consolidated e-invoices

`is_consolidate` (boolean, on the top-level document) is the canonical signal that a document is a consolidated e-invoice. Callers setting it to `true` don't need to populate `line_items[].classifications` — `UBL::getDocumentLineItemsSchema()` automatically emits a single `004` classification with `listID=CLASS` on every line, and skips any tariffs. The legacy contract (every line tagged with classification `004`) still works and is treated identically — `UBL::isConsolidated($document)` recognizes both. The flag form is preferred for new callers.

Detection is **per-document** (not per-submission-batch): mixed batches where some documents are consolidated and others aren't are persisted correctly.

## Rounding amount

`payable_rounding` (optional flat key) maps to `LegalMonetaryTotal.0.PayableRoundingAmount.0._` (+ `currencyID`), written between `TaxInclusiveAmount` and `PayableAmount` (UBL 2.1 order) by `UBL::getDocumentTotalsSchema()`, rounded to 2dp by the builder, and only when that rounded value is non-zero — a 0/null/missing/sub-cent value emits no element, so existing callers' output is unchanged. Both `restoreJson()` and `restoreXml()` read it back as `payable_rounding`. The package never computes it: the caller keeps `grand_total` (before rounding), `payable_total` (after) and `payable_rounding` consistent. Whether LHDN enforces Payable = TaxInclusive + Rounding is unconfirmed pending a preprod submission (see `docs/lhdn-references.md`). Validator rule is `nullable|decimal:0,2`.

## Queued submission, lock and status sync (v1.5.0)

All additive: plain `submitDocuments()` behaves as before. Design decisions are TJ's, 2026-10-12; do not undo them casually.

**Parent link and client resolution.** `Contracts\ResolvesMyinvoisClient::configureMyinvoisClient(Myinvois)` is implemented on the parent model; `Myinvois::clientFor(Model)` (static) returns a fresh `app('myinvois')` (so a fake applies) run through it, or the plain config cascade without the contract. The worker and the sweep use it, so no credential is ever in a job payload. `forParents(array $numberToModel, ?string $lockOwner)` stamps `parent_type`/`parent_id` when rows are created (the observer then writes `submitted` to the parent immediately) and takes the lock; `Myinvois::rowNumbers($document)` is the row-number rule (invoice number, or each line description when consolidated); every row must have a parent (`InvalidArgumentException` before any network call). `forParents()` and `queueSubmission()` also refuse parents that resolve (`clientFor`) to different clients (client id, on-behalf-of, preprod): `Myinvois::assertSingleClient()` throws `InvalidArgumentException`, because one POST is signed with one client's credentials; the worker re-checks through `forParents()` and reports `SubmissionFailed(error)`. `configureMyinvoisClient()` runs once per distinct parent (here, then on the worker): keep it cheap. `assertSingleClient()` cannot detect mixed clients under `Myinvois::fake()` (one shared instance, so every parent looks the same).

**Lock** (`Support\SubmissionLock`). Cache lock per parent and environment, key `myinvois:submit:{prod|preprod}:{morphClass}:{key}`, no migration, no new `Status` case. Store `services.myinvois.lock_store` (default store), TTL `lock_seconds` (300). One owner token per submission across all its parents, all or nothing, taken in sorted key order. Inside the lock `assertSubmittable()` refuses a parent whose latest row in that environment is SUBMITTED or VALID. Conflict or refusal throws `MyinvoisInFlightException` (before anything is sent). `submitDocuments()` frees the lock (own or passed-in owner) once rows are written or on a definite failure (including a missing key/certificate or an uncovered row, which are checked before the POST but after a queue job's lock was taken), and **keeps it until the TTL after an ambiguous failure** (decision: no retry, no extra recovery; the user resubmits after the TTL). Ambiguity is `MyinvoisException::mayHaveReachedMyinvois()`: true only for a `MyinvoisUnavailableException` on the POST that is a network failure/timeout or 5xx; false for token-endpoint failures, 429, auth, permission. An unexpected non-Myinvois exception after the POST started (or a failure saving rows after LHDN accepted) also keeps the lock; a plain `\Exception` is a configuration error thrown before sending. `postStarted()` tells a caller which side an unknown exception fell on.

**Jobs** (`Jobs\SubmitDocuments`, `Jobs\PollSubmission`, config under `services.myinvois.*`: `queue_connection`, `queue`, `lock_store`, `lock_seconds`, `sync_schedule`, `sync_limit`). `Myinvois::queueSubmission($docs, $parents, $context)` validates, takes the locks, dispatches `SubmitDocuments` (`ShouldBeEncrypted`; payload = flat documents, parent references `{type,id}`, preprod flag, lock token, scalar context; never a key/cert/secret/token) and returns. The worker: resolve parents (deleted parent -> event), `clientFor(first parent)`, refuse when the client's preprod differs from the carried flag, then `forParents(...,$owner)->withoutPolling()->submitDocuments()`, then fire `SubmissionAccepted` and dispatch `PollSubmission`. Retry (release) only when LHDN definitely did not get the request: token failure or 429, `Retry-After` else 30/60/120s, three retries counted in the cache (a rate-limiter wait must not use them up), then `SubmissionFailed(unavailable)`. Ambiguous failures: no retry, lock kept, `SubmissionFailed(ambiguous)`. Jobs never sleep: `MyinvoisThrottledException` -> `release(availableIn)`. `$tries = 0` with `retryUntil()` because a release for the limiter counts as an attempt in the queue; `$maxExceptions = 3` and `backoff()` (30/60/120s) on both jobs are only the net for an exception nothing handles, otherwise the worker re-runs it with no delay forever. Client resolution and the result handling are caught inside the job (pre-POST: report, free the lock, `SubmissionFailed(error)`; after acceptance: report only, a rerun would only fake a failure). A listener exception never stops package work: `SubmissionAccepted`/`Failed` (and the poll's events) are fired through a `report()`-ing wrapper, after the poll is dispatched; `DocumentStatusChanged` is held back by `MyinvoisDocumentObserver::deferEvents()` while rows are written and fired after the last one, also through `report()`. The run marker (`myinvois:submit-run:{lock owner}`) is a state, never a bare flag, and it is ownership-aware: each `handle()` run gets a random run id and stores `claimed:<runId>` (TTL `CLAIMED_SECONDS` 150 = `$timeout` + 30); a redelivery that finds `claimed:<other>` proceeds and overwrites it with its own id. The lock check and `assertSubmittable()` do NOT stop two such copies (same owner token, no rows yet): the ownership check does. `Myinvois::beforePost()` (called in `sendRequest()` right before the submission POST leaves, after token and rate limiter, so a token failure or throttle never reaches `posting`) runs `postingHook()`, which under a short `Cache::lock` (`{runKey}:guard`, also taken by `claimRun()` so get+put is atomic against a takeover) verifies the marker is still `claimed:<ownRunId>` (an absent, expired marker also counts as ours) and sets `posting`; otherwise it throws the internal `RunSupersededException` before the request leaves. `submit()` catches it ahead of the generic catch: no announcement, no lock release (the lock is shared with the copy that took over; the exception is deliberately not a `MyinvoisException` so the client keeps the lock), and `handle()` neither marks `done` nor deletes the marker. The hook runs once per run (a 401 retry re-sends through it). Right after `submitDocuments()` returns with rows the marker becomes `accepted:<submissionUid>` (only from `posting`), `done` once `handle()` finishes (`SETTLED_SECONDS` 86400 for `posting`/`accepted`/`done`: they must outlast any `retry_after`, and all are safe to keep). A redelivery that finds `posting` -> `SubmissionFailed(ambiguous)` once, no POST, lock untouched, marker `done`; `accepted` -> dispatch `PollSubmission` and fire `SubmissionAccepted` from the saved rows, marker `done`; `done` -> silent. `retryLater()` drops the marker only if it is still this run's: its `claimed:<runId>`, or the `posting` this run set itself (a 429 on the POST: LHDN did not take it). The escape path in `handle()` drops only this run's `claimed` (an exception after the POST started keeps `posting`, so the retry reports ambiguous). Neither ever deletes another copy's marker. Keep the queue connection's `retry_after` above the job `$timeout` (120s; the default 90s is too low). `queueSubmission()` registers `DB::afterRollBack()` to free its locks when called inside a transaction (afterCommit jobs are discarded on rollback). Known limitation: if it runs inside a nested transaction that commits and an outer transaction then rolls back, Laravel discards the rollback callback, so the lock only lapses at its TTL (no cheap fix; documented in the README). Both jobs set `afterCommit` in the constructor (Queueable declares the property). `PollSubmission` releases at 10/20/40/60/120/300/600s keyed on `attempts()` (a throttle or 429 wait uses a step), then stops; the sweep is the net. It announces once (cache guard) and is read-only, so idempotent. `SubmissionFailed::$reason` values are constants on the event. A failed outcome is an event, never a failed queue job.

**Events**: `SubmissionAccepted`, `SubmissionSucceeded`, `SubmissionFailed`, `DocumentStatusChanged($row, $from, $to)`. The last is fired by `MyinvoisDocumentObserver` (created: `$from` null; updated: only when `status` changed) after the parent status is written, from any path. Laravel builds a new observer object per event, so the pending change lives in a static `WeakMap`. Events carry parent references and document numbers, never buyer details.

**Sweep** (`Support\StatusSync`, `Console\SyncCommand`, `php artisan myinvois:sync {--limit=} {--dry-run} {--include-valid}`). Outbound rows (`is_inbound` false/null) with `document_uuid` and `submission_uid`, environment from the package's own `getSettings('preprod')` (preprod: `is_preprod = true`; production: false or null), status SUBMITTED; **INVALID is final and never swept** (decision 3), with `--include-valid` also the parent's latest VALID row younger than 72h. Grouped by `submission_uid` (id-only query first, newest first so a pile of never-resolving old submissions cannot fill the limit every run and starve recent ones (an old stuck one is reached only after newer ones clear), `--limit` counts submissions, default `sync_limit` 100) so a consolidated submission costs one call. Each submission uses `clientFor(parent)`; a client whose credentials fail is skipped for the rest of the run; other errors are reported and the sweep continues; the command exits non-zero on any error. Status writes go through `getSubmission()` -> `updateMyinvoisDocuments()` so the observer's latest-submission rule holds. Preprod rows created by a per-org preprod switch inside a production app are not swept from production (accepted, decision 7). The service provider registers the command and, only when `sync_schedule` is set (`'hourly'` or a cron expression; **off by default**), schedules it `withoutOverlapping(30)->onOneServer()` via `callAfterResolving(Schedule::class)`.

**Fake.** `MyinvoisFake` honours `forParents()` (stamping, lock, refusal), never sleeps (`pollAfterSubmit()` is a no-op), overrides `getSubmission()` to resolve `submitted` rows, and has `pollResolvesTo('valid'|'invalid', ?errors)` for "submitted now, resolved when the poll job runs"; `resolveStatus('invalid')` makes the rows invalid at once, with a `validationResults` message so `getErrors()` is not empty. It still cannot simulate HTTP failures: package tests use `Http::fake()` for those (`QueuedSubmissionTest`, `ParentLinkAndLockTest`, `SyncCommandTest`; the fake flow is in `MyinvoisFakeQueueTest`).

## UBL builder conventions

`UBL.php` uses `data_set($schema, 'Invoice.0.X.0._', $value)` heavily. The `.0.` indexes and trailing `._` value keys come from the `Noki\XmlConverter\Convert` JSON↔XML format — they're load-bearing, not arbitrary. When adding fields, follow the existing dotted paths exactly.

TIN handling: `getDocumentTINSubschema()` maps the flat `tin`/`brn`/`nric`/`passport`/`army` keys to UBL's `PartyIdentification` entries. `Enums/TinType.php` defines the special general-public / foreign / government TINs used when a buyer has no real TIN.

Codes (countries, states, currencies, MSIC, units, taxes, classifications, payment-modes, document-types/versions) live as static JSON in `json/codes/` and are accessed via `Helpers/Code.php`:

```php
Code::countries()->value('Malaysia');   // → 'MYS'
Code::states()->get('Kuala Lumpur');    // auto-prefixes 'Wilayah Persekutuan'
```

`Code` is a `__callStatic` magic class — the snake-slug of the method name selects the JSON file. `getValueKey()`/`getLabelKey()` map per-file column conventions (e.g. `document-versions` uses `Version` as the value key, others use `Code`).

## Persistence model

`database/migrations/myinvois_001_myinvois_documents.php` creates `myinvois_documents` with a ULID PK, polymorphic `parent_type`/`parent_id`, and JSON `request`/`response` columns. The migration is a no-op if the table already exists — host apps publish/run it once.

`Models/MyinvoisDocument.php` is morphTo'd to the host model. The `Status` enum (`submitted`/`valid`/`invalid`/`cancelled`) drives the `color()`, `label()`, and `is()` helpers used in UI.

`Models/Traits/HasMyinvoisDocument` is mixed into host-app models that own invoices. It resolves the document model class via `MyinvoisDocument::$useModel` (Sanctum/Cashier-style swap) — defaults to the package's own `Jiannius\Myinvois\Models\MyinvoisDocument`, but host apps can extend it and register their subclass from a service provider: `MyinvoisDocument::useModel(\App\Models\MyinvoisDocument::class)`. The trait adds `myinvois_status` / `myinvois_preprod_status` casts and the morph relations; the observer in `Observers/MyinvoisDocumentObserver` writes back to those columns on the parent whenever a child doc is saved (preprod vs prod kept separate). The write goes through the base query builder (`toBase()->update()`) on purpose: the Eloquent builder would add `updated_at`, and a status refresh is not a content edit of the parent.

`isCancellable()` enforces the LHDN 72-hour cancellation window — preserve this when touching cancel logic.

## Environment / endpoints

Two base URLs hardcoded in `Myinvois::$baseUrl`: `prod` (`api.myinvois.hasil.gov.my`) and `preprod`. The `preprod` flag also controls the validation share-link host in `MyinvoisDocument::getValidationLinkAttribute()`. `getEndpoint()` prepends `/api/v1.0/` unless the URI starts with `/` (only the OAuth `/connect/token` endpoint uses the bare form).

## Testing

PHPUnit (not Pest — Pest's latest caps at PHPUnit ^12, this package is on PHPUnit 13 via `testbench` 11 / Laravel 13). Run `composer test` or `vendor/bin/phpunit`. Suites: `tests/Unit` (pure helpers — `Code`, `UBL` build/restore/sanitize, `Signature`, `Validator`, enums, all no-network) and `tests/Feature` (testbench + in-memory sqlite — model casts/scopes, the `HasMyinvoisDocument` trait, observers, and the `Myinvois` API layer / `submitDocuments` pipeline under `Http::fake()`; plus the queued flow: `ParentLinkAndLockTest`, `QueuedSubmissionTest` (jobs run directly with `withFakeQueueInteractions()` / `assertReleased(delay)`), `SyncCommandTest`, `MyinvoisThrottleTest`, `MyinvoisFakeQueueTest`, and `BoostGuidelineTest`, which compiles the Boost guideline with Blade). `phpunit.xml` runs with `failOnWarning`/`failOnRisky`.

Fixtures in `tests/Fixtures/`: `DocumentFixture` (deterministic flat-array inputs — no `now()`/`time()`, unlike `Helpers/Sample.php`), `CertFixture` (throwaway RSA keypair + self-signed cert, memoised per process so signature digests are reproducible), and `Order` (a polymorphic parent model using the trait). Signature tests freeze time with `Carbon::setTestNow`. The suite covers the build/sign/persist logic locally, but true end-to-end acceptance still requires the preprod MyInvois sandbox via a host app — there is no local way to dry-run an actual submission.

## Things to know before editing

- When changing document shape or signing, run `composer test` first — the golden-path assertions in `tests/Unit/UblBuildTest.php` and `tests/Unit/SignatureTest.php` guard the load-bearing UBL paths and XAdES digests. End-to-end still needs the preprod sandbox.
- Document shape changes must stay backwards-compatible with the flat array contract in `Helpers/Sample.php` — that's the documented input format for callers.
- The signing flow is order-sensitive: `UBL::build` must run before `Signature::build`, and the JSON serialization inside `Signature::toJson` must not be reformatted.
- `Validator.php` runs Laravel validation against the flat input shape (not the built UBL). Call `app('myinvois')->validator($doc)` before submission to surface user-friendly errors.
- The Laravel Boost AI guideline at `resources/boost/guidelines/core.blade.php` is host-app-facing documentation, picked up by `boost:install` in any host project. Keep it in sync when changing the public API surface (`Myinvois` methods, the `HasMyinvoisDocument` trait, the document input contract). Validate with the Blade compiler before tagging — `<code-snippet>` blocks must be wrapped in `@verbatim` / `@endverbatim`.
